01 Alur kerja: dari topik ke EPUB

Semuanya dikendalikan satu skrip orkestrator, scripts/generate_book.sh, yang menjalankan 7 langkah berurutan. Setiap langkah menulis file nyata ke disk, jadi Anda bisa berhenti, memeriksa, mengedit, lalu melanjutkan tanpa mengulang dari nol. Langkah ke-7 (paket pemasaran KDP) hanya jalan kalau Anda meminta --marketing.

Yang terjadi di setiap langkah

LangkahProsesOutputCatatan
1 · Outline Model diberi topik + genre + audiens + jumlah bab dan target kata persis seperti argumen CLI, lalu mengembalikan struktur # Judul / ## Subtitle / ### Chapter N: Judul. outline.md Kalau tidak ada satu pun heading Chapter N: yang bisa dibaca, pipeline berhenti dan menampilkan 5 baris pertama outline — bukan menulis bab berjudul “Chapter 1: Chapter 1”.
2 · Bab Satu panggilan per bab. Model menerima outline + daftar bab yang sudah ditulis + ekor bab sebelumnya (untuk suara/kesinambungan), dan wajib mengembalikan badan bab saja. chapter_01.md … Output dibersihkan dari “Sure! Here is the chapter…”, fence ``` penbungkus, heading duplikat, “Word count: 412”, dan sign-off — kode blok asli di buku teknis tetap utuh.
3 · Appendices Preface, introduction, dedication, acknowledgments, epilogue, glossary, discussion guide, further reading. File markdown per bagian Hanya berjalan kalau GEMINI_API_KEY ada (skrip ini khusus Gemini). Bisa dilewati dengan --skip-appendices.
4 · Referensi Merangkum sumber/bab menjadi bibliografi. final_bibliography.md Kalau dilewati, bagian “References” otomatis tidak dibuat — tidak lagi menggagalkan compile.
5 · Orisinalitas Model memberi ORIGINALITY: n/10 per bab; angkanya diparsing numerik. Nilai: 8–10 lulus · 6–7 peringatan · <6/ tak terbaca = ditandai Ini heuristik, bukan database plagiarisme. Jangan jadikan bukti legal.
6 · Compile Menggabungkan outline + bab → manuscript, menambah title page, TOC, copyright page, About the Author, lalu ekspor lewat pandoc. exports_<timestamp>/: EPUB, HTML, Markdown, print-ready HTML, book.css, metadata.yaml PDF via LaTeX kalau pdflatex/xelatex terpasang; kalau tidak, dibuat *_pdf_print.html (Print → Save as PDF dari browser). MOBI/AZW3 butuh Calibre.

02 Lapisan AI: provider apa saja, dan URL custom

Semua panggilan AI lewat satu pintu: scripts/multi_provider_ai_simple.sh. Ia mendeteksi provider yang tersedia, mencoba berurutan, dan (kalau diminta) dikunci ke satu provider.

Gemini→ Ollama lokal→ Groq→ Anthropic / Claude→ Custom (OpenAI-compatible)

Urutan di atas berlaku untuk mode auto. Provider yang tidak dikonfigurasi dilewati, bukan digagalkan.

ProviderVariabelCatatan
GeminiGEMINI_API_KEYDisarankan; rotasi 7 model + cooldown saat kena rate limit. System prompt dikirim via systemInstruction.
Ollama (lokal)tanpa key
http://localhost:11434		Gratis & privat. Kalau server tak menjawab, terdeteksi dalam ±2 detik (dulu menggilir 7 model dengan pesan menyesatkan).
GroqGROQ_API_KEYFallback cepat.
Anthropic / ClaudeANTHROPIC_API_KEY
ANTHROPIC_MODEL		Adapter sendiri, karena format API berbeda: system prompt sebagai field terpisah, auth x-api-key + anthropic-version.
Custom (apa pun yang kompatibel OpenAI) CUSTOM_API_BASE_URL
CUSTOM_API_KEY
CUSTOM_MODEL		 OpenAI, OpenRouter, DeepSeek, Together, Mistral, xAI, LM Studio, vLLM, llama.cpp, gateway internal.

Empat cara menulis URL, semuanya sah

export CUSTOM_API_BASE_URL="http://localhost:1234/v1"                 # → /v1/chat/completions
export CUSTOM_API_BASE_URL="http://localhost:1234/v1/"                # slash akhir dinormalisasi
export CUSTOM_API_BASE_URL="http://localhost:1234/v1/chat/completions" # tidak jadi dobel
export CUSTOM_API_BASE_URL="https://gw.internal/proxy/llm/v1"       # prefix gateway tetap jalan

./scripts/generate_book.sh --topic "Topik Anda" --provider custom

Pilih provider: --provider auto|gemini|ollama|groq|anthropic|openai|custom. Kunci bersifat tegas: kalau provider yang dikunci tidak punya key/URL, jalannya berhenti dengan pesan variabel mana yang harus diisi — tidak diam-diam pindah ke provider lain.

Cek koneksi kapan saja: ./scripts/multi_provider_ai_simple.sh status dan … test.

03 Gerbang kualitas: kapan pipeline berhenti

Sebelum perbaikan, kegagalan sering tak terlihat (teks kosong dianggap sukses, bab berisi placeholder, build gagal tanpa penjelasan). Sekarang kondisi-kondisi ini menggagalkan run secara eksplisit:

  • Outline tidak punya heading Chapter N: yang bisa dibaca → berhenti + cuplikan outline.
  • Semua bab gagal dibuat → berhenti; sebagian gagal → dihitung dan dilaporkan.
  • Provider mengembalikan badan kosong / hanya spasi / error JSON → dihitung gagal, bukan “✓ Generated”.
  • Tidak ada provider sama sekali → berhenti dalam ±4 detik dengan daftar provider yang dicek (dulu ±21 detik).
  • Compile tanpa bibliografi → bagian References dilewati, build lanjut.
  • Aset gambar tidak diberikan → tidak ada satu pun gambar disisipkan (dulu logo penerbit orang lain ikut masuk).

Artwork bersifat opt-in. Setiap compile menampilkan ringkasan seperti icon: (none) / logo: logo-saya.png / author photo: (none) / back cover: (none), jadi Anda selalu tahu apa yang akan tercetak di buku — tidak ada kejutan.

05 Bisa menghasilkan buku “sekelas profesional”?

Mari dipisahkan antara mesin dan isi, karena jawabannya berbeda:

Mesin (tooling) — ✅ sudah level produksi

Alur bab → manuscript → EPUB/HTML dengan title page, TOC, copyright page, metadata, daftar isi koheren, dan verifikasi bahwa EPUB-nya benar-benar valid (saya uji baca ulang isinya). Untuk buku non-fiksi praktis, hasil formatnya sudah layak upload KDP.

Isi (prosa) — tergantung model + editing Anda

Draft AI tanpa editan cenderung generik: paragraf seragam, sedikit contoh konkret, kadang mengulang. Dua buku yang sudah terbit dari toolkit ini memang lewat review dan penyelesaian manual — README-nya sendiri menyebut “manual review and cover design recommended”.

Rapor per aspek

AspekNilaiAlasan
Struktur & format eksporBaikEPUB/HTML/MD tervalidasi; PDF butuh LaTeX (tanpa itu ada print-ready HTML).
Metadata & halaman wajibBaikJudul, subjudul, penulis, penerbit, tahun, ISBN (opsional), copyright.
Cover & artworkPerlu tenaga AndaOpt-in sekarang, tapi kualitas cover tetap tanggung jawab Anda — ini faktor konversi penjualan nomor satu.
Kualitas prosa tingkat pertamaPerlu editanPerlu satu-dua putaran revisi; mesin bantu optimized_chapter_handler.sh ada, tapi tak ada jaminan gaya.
Riset & faktaLemahTidak ada fact-checking, tidak ada akses web saat menulis; bibliografi bersumber dari model.
Kepatuhan platformTanggung jawab AndaPengungkapan konten AI, batas jumlah judul, dan hak cipta ada di sisi Anda.

Jalan realistis menuju “profesional”: pakai repo ini sebagai pabrik draft + perakit, lalu investasikan waktu Anda di 4 hal ini — (1) editing menyeluruh, (2) tambah contoh/cerita/fakta nyata, (3) cover yang didesain sungguhan, (4) verifikasi sumber dan pengungkapan AI. Itu yang membedakan buku AI yang “lolos” dari yang “laku”.

06 “AI enhancer” / mode agent — bisa, dan justru langkah berikutnya

Status sekarang: ini bukan agent, ini pipeline batch deterministik. Ia tidak merencanakan, tidak memutuskan, tidak memakai alat lain, tidak mengoreksi dirinya sendiri, dan tidak ingat apa pun antar-bab selain ekor bab sebelumnya. Perilakunya: “panggil API → tulis file → lanjut”.

Yang berubah kalau ada lapisan agent

SEKARANG — batch
outline→ bab 1..N→ cek skor→ compile
DENGAN AGENT — loop plan → act → critique → revise
Planner→ Writer→ Critic (rubrik)→ Reviser↻ Compile & verifikasi
TOOLS yang bisa dipakai agent
web search / riset fakta market data (KDP) generate_image (cover) compiler buku ini grammar check document/notes Anda

Kombinasi dengan agent lain — tiga pola yang praktis

1. Repo sebagai tool untuk agent Anda

paling cepat

Bungkus skrip yang ada sebagai perintah yang bisa dipanggil agent: generate_outline, write_chapter, critique_chapter, compile_book. Agent (Claude Code / Cursor / ChatGPT / LangGraph / n8n) yang memegang keputusan, repo ini yang mengeksekusi.

2. MCP server

paling rapi

Ekspos kemampuan repo sebagai MCP tools, sehingga agent apa pun yang mendukung MCP bisa “menulis buku” dengan memanggil tool tersebut — sekaligus menggabungkannya dengan Notion/Drive/Sheets sebagai sumber riset dan penyimpanan naskah.

3. Agent di dalam repo

paling mandiri

Tambah scripts/agent_book.sh: planner menyusun rencana bab → writer menulis → critic menilai dengan rubrik (kejelasan, contoh konkret, kesesuaian audiens) → reviser memperbaiki bab yang di bawah ambang, maksimum N putaran, lalu compile. Itu mengubah “generate sekali jadi” menjadi “tulis, nilai, perbaiki”.

Yang paling terasa bedanya

  • Riset fakta — agent bisa mencari dan memverifikasi sebelum menulis; ini kelemahan terbesar pipeline sekarang.
  • Konsistensi panjang — ringkasan/“bible” buku disimpan dan dipakai ulang, bukan cuma ekor bab sebelumnya.
  • Penilaian berulang — bab yang lemah diperbaiki otomatis, bukan diterbitkan apa adanya.
  • Benchmark pasar — agent bisa mengambil data niche, membandingkan kompetitor, lalu menyetel outline.
  • Multimodal — cover, diagram, dan tabel dibuat sebagai bagian dari alur, bukan tambalan belakangan.

Rekomendasi saya (jika Anda mau saya kerjakan): mulai dari pola 1 + 3. Pola 1 memberi hasil tercepat (agent Anda langsung bisa memakai repo ini), pola 3 memberi lompatan kualitas isi karena ada loop critic → revise. MCP (pola 2) menyusul begitu kedua itu stabil.

07 Paket pemasaran KDP: deskripsi, keyword, kategori

Sampai v1.6.0, ada satu lubang antara “buku selesai” dan “buku terbit”: Anda harus menulis sendiri deskripsi jualan, memilih 7 keyword, dan menentukan 3 kategori di KDP. Sekarang itu dihasilkan scripts/generate_marketing_copy.sh ke dalam folder <buku>/marketing/.

BerkasIsi
description.htmlDeskripsi KDP, siap tempel ke tampilan Source/HTML
description.txtVersi tanpa tag HTML — untuk blog, email, siaran pers
keywords.txtTepat 7 frasa keyword, satu per baris
categories.md3 usulan kategori Amazon lengkap dengan jalurnya
social_copy.mdBlurb pendek, thread, email peluncuran, bio penulis
kdp_listing.mdSemuanya dalam satu lembar + laporan validasi
 
# bangun paketnya
./scripts/generate_marketing_copy.sh v3/<folder-buku>

# periksa saja (tanpa AI, tanpa internet) — keluar dengan status ≠0 kalau ada yang ditolak KDP
./scripts/generate_marketing_copy.sh v3/<folder-buku> --check

# atau jalankan sebagai langkah terakhir pipeline
./scripts/generate_book.sh --topic "Topik Anda" --chapters 8 --marketing

Aturan KDP yang ditegakkan, bukan sekadar disarankan

  • 4.000 karakter termasuk tag HTML — deskripsi yang kepanjangan dipotong di batas kalimat, tidak pernah dibiarkan melewati batas. Tag yang tidak dikenal dibuka (tag dibuang, teksnya tetap ada), atribut gaya dibuang.
  • Emoji dilarang KDP — dibuang otomatis sebelum Anda menempelkannya, huruf beraksen seperti café tetap aman.
  • 7 kolom keyword × 50 karakter — dipotong di batas kata, duplikat dibuang, dan urutan “paling penting dulu” dari model dipertahankan.
  • 3 kategori — disertakan jalur lengkap supaya mudah dipilih di KDP.

Yang diperingatkan sebagai pemborosan ruang: kata yang muncul di dua kolom keyword (Amazon hanya mengindeks sekali), frasa yang mengulang kata di judul (sudah terindeks), satu kolom yang hanya berisi satu kata pendek padahal muat frasa 50 karakter, dan deskripsi yang mengulang sebuah keyword tiga kali atau lebih (bau keyword stuffing yang bisa ditolak KDP).

Batas jujurnya: Amazon tidak menyediakan API publik untuk mengunggah buku, jadi langkah terakhir tetap manual — buka KDP, tempel deskripsi, isi 7 keyword, pilih 3 kategori. Yang bisa diotomasi adalah menyiapkan isinya dan memastikan isinya tidak akan ditolak.

08 Gambar: sampul & ilustrasi bab, gratis dulu

Anda benar soal Pollinations: itu memang layanan gambar gratis tanpa API key, tanpa daftar, dan praktis tanpa batas untuk pemakaian wajar. Jadi tidak wajib memakai model gambar berbayar. Pipeline sekarang mencoba penyedia secara berurutan dan memakai yang pertama berhasil:

#PenyediaBiayaSyaratCatatan
1pollinationsGratistidak ada Pollinations.ai, default model flux. Tidak perlu key. POLLINATIONS_TOKEN opsional untuk limit lebih longgar.
2a1111GratisGPU sendiri Stable Diffusion lokal (AUTOMATIC1111 / SD.Next dengan --api). Tanpa kuota, tanpa internet.
3openaiBerbayarAPI key Endpoint /images/generations apa pun yang kompatibel OpenAI. Dipakai hanya kalau key diisi.
 
# lihat penyedia mana yang aktif di mesin Anda
./scripts/image_gen.sh status
./scripts/image_gen.sh test      # uji semua penyedia, cetak ✅/❌ per penyedia

# kompilasi dengan sampul AI + satu ilustrasi per bab
./scripts/compile_book.sh v3/<folder-buku> all 1 --generate-cover --illustrate

# seluruh pipeline sekaligus (topik → bab → buku bergambar)
./scripts/generate_book.sh --topic "Topik Anda" --images

# ganti penyedia cukup satu variabel
export IMAGE_PROVIDER=pollinations   # gratis (default di mode auto)
export IMAGE_PROVIDER=a1111          # Stable Diffusion lokal
export IMAGE_PROVIDER=none           # matikan gambar sepenuhnya

Kenapa sampul dibuat dua langkah

Model difusi masih sering salah menulis huruf, jadi model hanya melukis gambar tanpa teks (prompt-nya tegas: “no text, no letters, no watermarks”, dan menyisakan ruang di sepertiga atas & bawah). Judul, subjudul, dan nama penulis baru ditempel oleh ImageMagick di atas pita transparan. Hasilnya teks selalu tajam dan ejaannya benar — sesuatu yang tidak bisa dijamin kalau teks diminta langsung ke model gambar.

Pengaman: file yang diunduh hanya diterima kalau lolos pemeriksaan magic bytes dan berukuran wajar. Halaman error HTML (404/429) atau unduhan terpotong tidak akan pernah lolos jadi sampul buku Anda. Kalau ImageMagick atau font tidak ada, gambar mentah tetap dipakai — kompilasi tidak gagal.

Catatan lingkungan: skrip sekarang memuat .env otomatis (lihat .env.example untuk daftar variabelnya, termasuk blok gambar). Tidak perlu source .env manual lagi — tapi export manual tetap menang kalau Anda mau menimpanya.

Dokumen ini merangkum keadaan repo pada rilis v1.7.0 (branch arena/1b3521bd-book-generator): 7 putaran perbaikan — compile stage, lapisan AI, provider custom, aset artwork, mode agent, gambar gratis, dan paket pemasaran KDP — dengan 65 tes otomatis lulus.

Semua angka di halaman ini berasal dari eksekusi nyata di sandbox: stub provider offline, verifikasi isi EPUB, dan pemeriksaan payload yang benar-benar dikirim ke endpoint.
